# 检验记录详情与附件管理子弹窗

## 本轮范围

仅在 V2 统一历史检验组件中实现“详情”和“报告附件”子弹窗，未保存用户截图、改动 P0、数据库、迁移、设备列表配置或历史检验样本。未提交或推送 Git。

- static/v2/inspection-record-dialogs.js：新增两个共享只读子弹窗、附件筛选函数。
- static/v2/inspection-history.js：两个操作转交共享子弹窗；报告和意见书保持原行为。
- static/v2/styles.css：子弹窗双列表单、问题分组、附件查询和单一纵向滚动容器。

- 本文、test-results.json 及 screenshots/ 内六张实际浏览器截图。

## 实现说明

两个入口均由 V2InspectionHistory 的当前设备与当前历史记录触发 V2InspectionRecordDialogs.open。参数保留设备类型、设备 ID 和检验记录 ID，并校验记录归属。没有两套数据或两份入口实现。

详情包含 13 个字段：检验机构、检验部门、检验员、检验性质、检验报告编号、检验类别、报告审核人、报告审核日期、报告审批人、报告审批日期、设备检验结论、检验日期、下次检验日期。机构和下次日期跨两列；只读字段未提供值留空。设备问题 6 项、管理问题 5 项均禁用；现有记录无问题类型，不预设缺陷。

附件表格为独立选择列，加序号、操作、附件类别、附件种类、标题、文件名、上传账号、上传时间，复用既有 recordTable 的分页、排序、选择和统计。现有记录无关联文件或分类关系，三个分类下拉保留空选项并明确说明，无下载或上传操作。文件名、日期范围与分类筛选有统一过滤逻辑，严格限定当前设备及检验记录。非法日期区间提示错误，重置清空条件和状态。

新子弹窗采用独立原生 dialog.showModal，位于父弹窗上方。父组件 DOM 保持原样，不重新渲染或清空。关闭、取消和 Escape 清理本层并恢复焦点与原滚动锁；父弹窗继续打开。每个子弹窗只有正文纵向滚动，附件表独立横向滚动。

## 实际测试

- 新用例：59 通过、0 失败、2 跳过。
- 共享历史检验回归：32 通过、0 失败、0 跳过。
- 合计：91 通过、0 失败、2 跳过。
- 跳过原因：压力管道装置没有既有检验记录，入口 A/B 无可点击记录。未伪造样本补齐测试。该类别保留正常空表，其余八类均验证双入口弹窗。
- 验证：13 字段及同记录值、11 项只读问题、附件表头顺序、日期错误/重置/空表/统计、跨设备与记录隔离、重复打开与关闭、父表选择分页状态、报告与意见书原行为。
- 1366、1920、390px 验证两个子弹窗布局、单一纵向滚动及宽表溢出时横向滚动。
- 无阻断性浏览器 console/pageerror、无写入请求。JS 语法检查通过。
- 初始红灯测试正确发现尚无子弹窗；实现后首轮一处测试错误要求 1920px 已完全容纳的表格必须发生横向滚动，已改为仅溢出时要求滚动，再验证通过。此过程保留在 failure.json，最终结果以 test-results.json 为准。
- 未执行 Django、数据库或全量设备列表测试。
