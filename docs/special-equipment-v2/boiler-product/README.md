# 锅炉产品管理 Demo

## 本轮范围与修改文件

只实现产品管理下的锅炉产品管理，沿用既有 boiler-product 菜单。其余五类产品页仍未开发。

- static/v2/boiler-product.js（新增）：独立产品配置、5条虚构样本、会话编辑、实际复制、浮动菜单和模拟产品检验信息。
- static/v2/app.js：接入产品行操作与既有主表、查询、导出能力，调用产品模块时传入现有弹窗/关闭/刷新/消息回调。
- static/v2/styles.css：产品表单、浮动菜单、固定列和响应式的限定样式。
- static/v2.html：加载产品模块。
- v2_server.py：仅增加产品静态脚本白名单，无产品业务后端接口。
- tests/v2/boiler-product.e2e.cjs（新增）：产品针对性浏览器测试。
- 本文、test-results.json、screenshots/ 下13张实际浏览器截图。

未修改设备/单位/人员样本，未操作P0/8010或原始数据库，未迁移、提交、推送或公网部署。未保存用户参考截图。

## 主表与数据

最新用户补充的“备注”位于最右侧。独立复选框列之外，完整10列为：
序号、操作、设备代码、产品名称、制造单位、产品型号、产品编号、设备类别、创建日期、备注。

没有额外补猜测表头。所有列有数据键，备注可查询后查看、编辑、列设置和CSV导出。
5条虚构产品使用独立 DEMO-BOILER-PRODUCT-xxx ID，属于产品记录，不是在用锅炉设备。类别复用现有演示锅炉类别，制造单位名称复用设备样本中的虚构制造单位。

查询支持设备代码/产品名称/规格/产品编号关键词，制造单位文本、类别精确匹配。首次进入和重置为空，查询后显示数据。复用排序、分页、选择、列设置和标签状态。
导出当前查询下全部匹配产品，按完整列配置顺序，不因隐藏列或部分选择漏导字段/记录。导入禁用并提示未提供文件解析。

## 产品编辑

标题“锅炉产品编辑”，30个字段按截图顺序配置：设备代码、产品名称、设备类别、产品编号、产品型号、合同号、生产编号、用户名称、是否出口、设计压力、设计温度、盛装介质、容积（m³）、额定蒸发量、额定热功率、额定蒸汽（出口）压力、额定蒸汽（出口）温度、制造单位名称、统一社会信用代码、制造许可证号、制造国家（地区）名称、制造日期、制造详细地址、制造规范、位号、许可范围、许可证级别、规格（t/h）、补录设备参数的单位、备注。

3个必填项：设备代码、产品编号、制造单位名称。设备类别双层选择，锅炉大类固定。校验必填、设备代码/产品编号唯一、数值格式及非负约束（温度允许负值）；日期使用原生日历控件。
保存时才更新选中产品。关闭丢弃草稿。保存后按现有查询与排序重新计算结果、统计和分页，不清空条件；重新打开与导出使用更新后的数据。错误提示可滚动到可见位置。

## 实际复制

复制读取当前产品属性，创建独立产品ID、设备代码和产品编号；连续复制避免冲突。新产品加入当前会话数组并立即重新计算当前查询总数；只在真正新增后提示“复制成功”及会话限制。
原产品不被覆盖。新记录可查询、编辑、再复制和导出。
产品检验数据存放于独立Map，以产品ID关联，因此复制产品不会复制检验信息或设备台账。

## 更多菜单及产品检验

菜单两项：修改记录（禁用并提示暂未开放）、检验信息。菜单在表格外浮动显示，支持再次点击、点击外部、滚动、窗口变化及Escape关闭，清理事件和行高亮。
不影响其他模块已实现的修改记录功能。

检验信息包含14项：检验机构名称、统一社会信用代码、检验责任主体单元、检验性质、检验人员、检验报告书编号、审核人员、审核日期、审批人员、审批日期、检验开始日期、检验结束日期、检验结论、办理状态。
机构与信用代码必填；机构输入可复用既有演示检验单位并带入信用代码。责任单元、报告书编号跨整行。开始、结束、审核、审批日期做先后校验。
保存仅进入当前产品会话数据，再次打开显示保存值；关闭丢弃草稿。不同产品独立，未录入时为空。下拉选项明确标注演示/模拟，不代表真实法定结论，不改变设备准用状态。
