## 字段和数据

38项名称、顺序、唯一ID通过自动核对，详见fields.json。第二步与第四步均直接使用同一字段数组。资料中的“单位组织机构代码”不映射为“统一社会信用代码”，没有值时保持缺失。

数据继续来自V2Personnel.rows，所属单位通过unitId查找V2InspectionUnits.rows，不复制单位档案。明确演示分类：
- DEMO-PERSON-002、004：检验人员。
- DEMO-PERSON-001、003：无损检测人员。

这是演示分类，不代表执业资格；不从ndt=否反推类型。两类型共用38字段，所以切换保留当前适用条件，不引入跨类型字段。

现有个人资格数组为空，缺值字段可配置但标记暂无数据，不补造证书。资格多个条件在同一条、personId正确的资格记录内计算；不拼接不同记录。结果选资格字段时按匹配的人员/资格展开，无资格但满足基本条件时资格列为空。只选基本字段时每人最多一行。

38项中没有应强行定义为数字的字段；考核号、证书号、邮政编码等保持文本，以保留前导零。通用执行器的数值和布尔分支使用单独合成测试验证，不向生产样本添加额外业务字段。

## 方案与规则

新增、编辑、执行、单条/批量确认删除仅作用于方案，不修改人员档案。首次及重置后列表为空，点击查询后筛选本机方案。创建人为“演示查询用户”，不冒充登录身份；创建时间以UTC保存，显示与日期筛选使用Asia/Shanghai。

表达式是group(and/or)和rule树，不使用eval。文本、枚举、日期、数字、布尔分别校验；支持区间、为空和非空；空值不当作0或否，普通“不等于”也不匹配缺失值。最多4层、60节点，空子组不可保存。第二步选字段，⊕添加条件；第三步添加/删除条件和子组。

至少一个结果字段才能保存。第四步勾选、上下移动、文字颜色和冻结均影响执行后的表格。CSV导出全部匹配行，使用配置字段顺序及当前排序，进行公式前缀转义。颜色/冻结不写入CSV。

存储键opencmms.v2.query-plans.person.v1，最多200个方案/1MB。仅保存元数据、字段ID、表达式和结果列配置，不保存人员快照或查询结果。敏感号码条件限制为虚构演示标识；不新增真实身份证、电话号码。存储失败保持编辑窗口并报错，不提示成功。损坏/失效存储报错且不静默覆盖。取消不保存草稿。不同浏览器或预览地址不共享localStorage，清理存储会丢失方案。
