# 人员信息管理 Demo

## 本轮文件

- static/v2/personnel.js（新增）：人员配置、四条样本、单位ID关联、人员档案与个人资格弹窗。
- static/v2/app.js：复用主页面查询、排序、分页、选择、列设置、CSV及标签页，增加人员操作路由、综合查询字段及高级查询配置。
- static/v2/more-dialogs.js：同一个修改记录组件新增 person 上下文；原 equipment、organization 支持保留。
- static/v2/styles.css：人员档案、资格查询及表格的限定样式。
- static/v2.html：加载人员模块（单位模块之后）。
- v2_server.py：仅增加人员静态脚本白名单，无新业务接口。
- tests/v2/personnel.e2e.cjs（新增）：人员模块针对性测试。
- 本文、test-results.json、screenshots/ 下 16 张实际浏览器截图。

未修改原设备和单位数据配置；不写 SQLite，不增加迁移，不改 P0/8010，不保存用户参考图片，不执行提交、推送或部署。

## 主页面

人员信息管理菜单使用既有 personnel 标识。首次进入及重置后为空，无条件查询后显示4条虚构样本。综合查询匹配姓名、DEMO身份证标识、所属单位名称；地区、持证状态、数据来源支持组合筛选。

独立选择列之后严格为11列：序号、操作、姓名、无损检测人员、证件号码、单位名称、地区代码、邮政编码、电话、手机、数据来源。

复用现有排序、分页、选择统计、列设置、导出及标签状态。单位名称列宽330px、地区代码220px，支持横向滚动。主表使用9个业务数据字段，另有序号与操作。导出当前查询下全部匹配人员，字段顺序与配置一致。导入禁用并说明演示限制，不进行伪导入。

## 人员与单位关系

人员以稳定 DEMO-PERSON-xxx ID 标识，通过 unitId 引用 V2InspectionUnits.rows。
单位名称、地址、电话、地区均按ID读取原单位记录，未复制一套机构数据源。样本姓名为“演示人员甲/乙/丙/丁”，身份证为 DEMO-ID-PERSON-xxx，不生成真实完整身份证号码；电话和手机为明确的 DEMO 标识。

人员类别通过无损检测人员和演示职务区别；数据来源有手工演示样本、模拟导入样本。持证状态为演示未持证/演示资料待核，均非真实资格判断。

## 三个弹窗

1. 编辑人员基本信息：内部标题“检验检测人员信息”，25个字段按参考顺序排列，姓名、性别、身份证、地区代码、单位名称5项红星。地区代码、电子邮箱、备注跨两列。单选、下拉、日期与文本均只读；单位选择按钮禁用并有说明。缺失字段留空，无保存操作。
2. 资格信息：申请类别、持证状态、批准项目、资格类别、持证级别、证书编号6项组合查询及重置；独立选择列之后为序号、操作、申请类别、资格类别、持证状态、批准项目、证书编号、批准日期、有效日期、考核机构。使用现有通用表格的排序、分页、选择和统计。个人资格集合独立于单位资质，以 personId 过滤，当前全部为空；新增、删除禁用并说明限制。
3. 历史修改记录：完全使用设备/单位已有的查询、日期校验及表格组件，entityType=person、entityId=人员ID，按人员身份过滤数据。10个表头与需求一致，不多加操作列。当前为空，不因查询、打开弹窗等只读动作产生记录，不冒称后端审计。

三弹窗均复用既有 dialog，正文为单一纵向滚动区域，表格允许独立横向滚动，关闭后保留主表筛选、排序、分页和选择。
