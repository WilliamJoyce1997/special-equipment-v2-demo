## 单位13项字段

名称及顺序严格核对：
机构名称、所在单位名称、所在单位统一社会信用代码、地区代码、机构地址、机构级别、机构地位性质、所代表发证机构名称、邮政编码、机构电话、电子信箱、网址、质检行业统一社会信用代码。

ID以organization.开头，第二步和第四步直接读取同一数组。字段类型为文本或枚举；电话号码、邮编及信用代码保持文本，不损坏前导零。

八种单位类型全部可建方案。仅检验单位通过V2InspectionUnits.rows取得现有4条虚构档案。监管机构、使用单位、设计单位、制造单位、维保单位、安装单位、其他单位无独立数据源，构建器和执行结果均明确提示“当前演示环境暂无该类型数据源”，返回0条，不从设备/产品的名称字符串拼装机构档案。

“所在单位名称/信用代码”没有明确父单位关联时留空，不挪用机构自身名称或信用代码。机构地位性质映射已有单位性质字段，无值留空。字段详细映射见unit-fields.json。

## 设备字段与取值

八种顶级类型：锅炉、压力容器、电梯、起重机械、场（厂）内机动车辆、大型游乐设施、压力管道、客运索道。

压力管道必须明确选择“压力管道装置”或“压力管道管线”，默认装置。每个方案只选择一个子类型；没有合并两集合或重复计数。子类型持久化并参与校验和字段ID解析。

queryFields从原subjectDefs/relatedDefs/parameterDefs/inspectionDefs及“本类设备档案补充信息”读取，原详情页也调用同一个definitions。另按原表头数组提供更变、历史检验、隐患、附件字段（不含选择、序号、操作等UI列）。关联表字段带表名区分，基本/相关/参数/检验区用分组说明区分同名字段，ID包含设备类型、原分组和字段键。

字段总数（包括关联表字段）：
- 锅炉285；压力容器209；电梯223。
- 起重机械204；场内机动车辆204；大型游乐设施204；客运索道204。
- 压力管道装置200；压力管道管线214。

九种数据源各有8条既有演示记录。自动测试将所有详情基础控件数量、字段标签、控件取值与queryFields/queryValue逐项比较，全部一致。清单见equipment-fields.json，计数见engine-results.json；不声称这些演示配置等同于真实监管系统法定完整字段。

字段类型优先取原定义/现有类型元数据，结合明确单位及已有数值类型适配数值条件。日期值按日期比较，添加时间等仍显示原完整时间。没有样本值的配置标注“暂无数据”，部分缺值标注“部分记录缺失”，不会补造数据。

更变、隐患、附件当前原表为空，因此相关查询值也是空。历史检验复用V2Dossier.histories，匹配发生在同一条历史记录内；结果按设备ID只输出一行，关联字段汇总匹配记录的非空去重值，以分号分隔。若仅选基本字段，每台匹配设备仍只有一行。不会将检验完成当作准用许可，不计算法定周期。

## 共用行为与隔离

三个入口使用同一套创建人/创建时间筛选、四步构建器、表达式执行、动态结果、列排序/颜色/冻结、分页、CSV和确认删除。对象改变后移除不适用字段与规则，结果字段全部失效时恢复当前对象默认字段；无效枚举条件需重新填写。

localStorage键：
- opencmms.v2.query-plans.person.v1（兼容原人员方案）。
- opencmms.v2.query-plans.unit.v1。
- opencmms.v2.query-plans.equipment.v1。

类型不同的方案不会混入其他页面，加载时校验domain和类型专属字段ID。每个入口有独立筛选、分页、排序、选中状态。只存方案元数据/条件/结果配置，不存实体快照或结果；保存失败报错，删除二次确认。创建人为明确演示身份，创建时间显示和日期筛选均使用上海时区。

## 保留限制

- 七种单位类型没有独立数据源，不在本轮补建。
- 设备详情中仅有展示配置的字段继续缺失，不以占位文字冒充真实值。
- 关联历史字段以分号汇总；不是独立逐检验记录的报表。
- 沿用已验收的窄屏策略：步骤切换、表格横向滚动；窄屏不冻结列以避免遮挡。
- 无后端持久化、真实认证创建人或真实监管数据接口。
- 本轮结束等待最终人工验收，不继续自主扩展。
